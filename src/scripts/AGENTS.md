# src/scripts

The site's plain browser scripts. Each one is a TypeScript module that a component or page pulls in with its own `<script>` block, and Astro bundles it. No framework, no React.

## Files

- `nav.ts`: the services dropdown and the mobile menu (spec 0004). `DESKTOP_QUERY` mirrors Tailwind's `lg` and the `--header-h` media query in `src/layouts/PageLayout.astro`; nothing enforces that the three agree.
- `nav-spy.ts`: the home page's scroll aware nav underline (2026-10-13), imported by `src/pages/index.astro` only. Reads `data-nav-section` (a band's nav href, from the `navSection` prop on `Section` and `Footer`; the footer stands for `/contact-us`) and `a[data-nav-item]` (the header's top level links, both copies); once 40% of a band has scrolled into view from the bottom of the viewport (a band taller than 2.5 viewports: once its top meets the top), or the page is at its bottom (then the last band, the footer), it moves `data-active` to that band's link, which draws the underline (the `nav-underline` bar in `Header.astro`, growing in from the left and shrinking away to the right). Above the first marked band it is the page's own link. `aria-current` never moves.
- `back-to-top.ts`: the back to top link's visibility, on every page (loaded from `src/layouts/PageLayout.astro`). Reads `data-back-to-top` and sets `data-shown` once the page is 0.8 of a viewport down; the hidden state is CSS in `PageLayout`, gated on `html.js`, so the link (a plain `#main` anchor) stays in view with no script.
- `counters.ts`: the stat counter (spec 0005), reads `data-count-to` and `data-locale`.
- `carousel.ts`: the service intros' photo crossfade (spec 0013), on `CarouselDots`. Reads `data-carousel`, `data-carousel-slide`, `data-carousel-controls`, and `data-carousel-dot`. The home hero no longer uses it (2026-10-11).
- `reveal.ts`: two separate halves (spec 0005). The scroll reveal (`data-reveal`, `data-reveal-stagger`) fades and rises a band once. A stagger child's delay counts within its batch, the children one scroll or filter brings into view together (2026-10-26), not its place in the whole container, so a long list never stacks up delay. The heading rule (`data-heading-rule`, look from the `heading-rule` utility in `src/styles/global.css`) draws the gold line on the way down and takes it back on the way up, every crossing.
- `parallax.ts`: the Project page's tile parallax (spec 0014, revised 2026-10-09), on motion's `scroll()`. Reads `data-parallax-photo` (the photo's frame) and `data-parallax-text` (the words) inside each tile, and marks the tile `data-parallax-on`, which grows the frame (`parallax-photo` in `global.css`) so the sliding photo never shows its edge.
- `enter.ts`: the Project page's load entrance on motion (2026-10-09). Reads `data-enter` (the step, 80ms each), held at opacity 0 from the first paint by the `data-enter` rule in `global.css` (2s failsafe), and marks each element `data-entered`. Leaves an element below the fold to `reveal.ts`, so it is imported after it. Since 2026-10-26 it also listens for `project-filter:change` (sent from the list by `project-filter.ts`; the name is written in both) and plays the same entrance on every shown tile on screen, 80ms apart, cancelling anything still moving first and leaving a tile `reveal.ts` still holds (inline `opacity: 0`) to it.
- `tile-shimmer.ts`: the Project tiles' loading shimmer (2026-10-26), on motion. Reads `data-tile-shimmer` (the tile, with one `img`), `data-shimmer` (the layer under the photo, shipped `hidden`), and `data-shimmer-band` (the moving band). For each photo not yet `complete` it unhides the layer, sweeps the band on a loop, and holds the photo at opacity 0; on `load` (then `decode()`) it fades the photo in over 500ms and stops the shimmer; on `error` it just stops. A photo already loaded is left alone.
- `hero-scroll.ts`: the Project page hero's scroll (2026-10-09), on motion's `scroll()`. Reads `data-hero-scroll` (the band) and `data-hero-layer` (each block of words, a wrapper of its own so it never shares an element with the entrance): the layers rise and spread apart, staggered, and fade to 0.5; the header (`data-site-header`) slides away by its sticky `top` and fades, and is marked `inert` once gone. All scrubbed, so scrolling up reverses it.
- `smooth-scroll.ts`: the desktop wheel glide on every page (spec 0016), on Lenis, loaded from `src/layouts/PageLayout.astro`. One instance (`lerp` 0.12, touch left native); it pauses while `body` carries the mobile menu's inline `overflow: hidden` (`nav.ts`), read through a `MutationObserver` so neither module imports the other. Anchor jumps glide through `scroll-behavior: smooth` in `global.css`, not Lenis.
- `globe.ts`: the presence band's dotted globe (spec 0017), on cobe, imported when the band is within 400px of the viewport. Reads `data-globe` (the box), `data-globe-layer`, `data-globe-canvas`, and `data-globe-marker` with `data-kind`, `data-lat`, `data-lon`; sets `data-globe-on` on the box (fades the globe over the flat map) and `data-front` on each marker facing the visitor (pops it in). Draws only while on screen, visible, and moving, and keeps drawing for a short settle after creation because cobe does not redraw when its land texture loads. `src/lib/globe.ts` copies cobe 2.0.1's projection, so a cobe upgrade means checking it again.
- `room-carousel.ts`: a project detail page's rooms band (spec 0018). Reads `data-room-carousel` (the root), `data-room-track` (a `carousel-track`, the native snapping scroller that works with no script) whose photos carry `data-room` (their room's index), `data-room-prev` / `data-room-next` (the buttons, shipped `no-js:hidden`), and `data-room-name` / `data-room-work` (each room's name and work list). Each press reads the current photo from `scrollLeft` and steps one; it glides, or jumps under reduced motion. The track loops (2026-10-29): the script adds an `inert`, `aria-hidden` copy of the last photo before the first and of the first after the last, and once a scroll settles on a copy (`scrollend`, or 150ms without a scroll event where that is missing) it jumps by the real photos' total width to the photo it copies, so a press or swipe past either end runs on round. On scroll (one check per frame) it moves `data-active` to the name and work list of the photo's room; the `room-name` and `room-work` utilities in `global.css` draw the change.
- `typewriter.ts`: the intro heading's typing (spec 0009, assumed), reads `data-words`.
- `tilt.ts`: the home showcase's 3D hover (2026-10-24), after daisyUI's `hover-3d`, on `ProjectShowcase`. Reads `data-tilt` (a tile, which stays still; its card tilts); while a mouse moves over it, writes `--tilt-axis` and `--tilt-angle` (up to 10deg, the edge nearest the pointer rising), `--tilt-depth` (4 times the tile's longer side), and `--glare-x` / `--glare-y`, once a frame. On leave the CSS springs the card back to no transform, and the script removes everything 600ms later, once the glare has faded where it was. The turn, springs, lift, and glare are CSS in the component. Mouse only; nothing under reduced motion.
- `project-filter.ts`: the Project page's filter (spec 0014, revised 2026-10-09). Reads `data-project-filter` (the form, holding the list's id), `data-project-filter-status`, and `data-project-filter-empty`; matches each form field's `name` against the same `data-` attribute on every tile, so a new filter is markup only. Its form ships `no-js:hidden`.
- `select-menu.ts`: the Project filter's dropdowns (2026-10-16), on `FilterSelect.astro`, a select only combobox (WAI-ARIA practices). Reads `data-select-menu` (the root, which gets `data-open`), `data-select-button` (the `combobox`, which keeps focus), `data-select-list` (the `listbox`, shown with `hidden`), `data-select-value`, and each option's `data-value` and `data-select-label`. State lives in the DOM (`aria-expanded`, `aria-activedescendant`, the hidden `<select>`'s value); a choice sets the `<select>` and dispatches a bubbling `change`, so `project-filter.ts` is unchanged. Opening and closing play on motion (the list fades, drops 8px, and unfolds over 200ms, options 25ms apart; it lifts away over 120ms), skipped under reduced motion; the state flips at once, and the list is hidden only once its close finishes, unless reopened. Running animations are found through `getAnimations()` and cancelled, so no handle is kept.

## Conventions

- Enhance markup that is already complete. The built HTML shows the finished state (full numbers, open nav panels, every band visible, every rule full width), so with no JavaScript, a failed script, or reduced motion the page is whole. No CSS rule hides anything waiting for a script, with one written exception: the `data-enter` hold in `global.css`, bounded by the `js` class, reduced motion, and a 2s failsafe.
- Reduced motion is a full stop: check `prefers-reduced-motion: reduce` first and move nothing.
- Leave nothing inline once an animation ends, so hover styles and classes own the element again.
- Hooks are `data-` attributes written in markup, never in content. A page that does not import a script leaves its hooks inert.
- Write to the DOM through `style.setProperty` / `removeProperty`, `setAttribute`, `classList`, or `replaceChildren`, never property assignment, because ESLint's `no-param-reassign` flags it (the reason is written in `counters.ts`).
- `motion` is imported here only: by `reveal.ts` (`animate` from `motion/mini` and `inView`), by `parallax.ts` and `hero-scroll.ts` (`animate` from `motion/mini` and `scroll`), by `enter.ts` (`animate` from `motion/mini`), by `tile-shimmer.ts` (`animate` from `motion/mini`), and by `select-menu.ts` (`animate` from `motion/mini`), nothing else from the package. `lenis` is imported by `smooth-scroll.ts` only, and `cobe` by `globe.ts` only, through a dynamic `import()`. Lenis writes the real window scroll, so `scroll()` timelines need no knowledge of it; a future inner scroll area gets `data-lenis-prevent`. Lenis (1.3) also stops every native `scrollend` on the window in the capture phase, an inner scroller's too, so a script waiting for one listens on `window` with `capture: true` and checks `event.target` (as `room-carousel.ts` does).
- A `scroll()` offset Motion can map to a named view timeline range (`start end`/`end start`, `start start`/`end start`, ...) runs on the browser's `ViewTimeline`, which insets the viewport by the page's `scroll-padding-top` (104px on desktop). Write the offset as numbers (`'0 0'`) when it must measure against the real viewport.
- Never animate `transform` or `translate` on the header: a running transform animation makes it the containing block of the fixed mobile menu panel, even when overridden.
- Timings follow the scroll reveal's language where things move together: 24px rise, 600ms, ease out. Behaviour changes are written down in `docs/design.md` under Focus and motion.
