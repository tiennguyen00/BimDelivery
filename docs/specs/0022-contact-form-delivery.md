# 0022 · Working contact form delivery

**Status**: Assumed
**Date**: 2026-11-26
**Authorized by**: tiennguyen00, during /develop

## Owed decision

How a contact form enquiry reaches the company inbox, and what protects the public endpoint from spam once the Cloudflare Turnstile captcha is removed. The scope listed this as "Working contact form delivery · needs a decision", and spec 0011 left the delivery path (and the server half of Turnstile) for later.

## Assumption built on

The engineer asked to remove the captcha from `/contact-us` and to have every enquiry emailed to `info@bimdelivery.vn`, using free options for now.

- **No captcha.** Turnstile is removed completely: the widget, `useTurnstile`, the `PUBLIC_TURNSTILE_SITE_KEY` env field and build variable, the `turnstileToken` request field, and the `errors.captcha` copy. This replaces spec 0011's AC-8 and AC-9, and the Turnstile parts of AC-10, AC-12, AC-17, and AC-20.
- **Delivery through Resend's free plan** (3,000 emails a month, 100 a day), the provider spec 0001 already named. The Worker calls Resend's REST API (`POST https://api.resend.com/emails`) with plain `fetch`, no SDK. The `info@bimdelivery.vn` mailbox stays on Zoho Mail. Resend only sends, from an address on the verified `bimdelivery.vn` domain, so its DNS records (a DKIM key and a `send` subdomain) sit beside Zoho's and change nothing about receiving mail.
- **The endpoint** is `src/pages/api/contact.ts`, the one route with `export const prerender = false` (spec 0001). Every page stays prerendered.
- **Spam guard, invisible to visitors**, checked in this order:
  1. Same origin: the `Origin` header must equal the request's own origin, else `403`.
  2. Rate limit: the Workers rate limiting binding `CONTACT_RATE_LIMIT`, 5 requests per 60 seconds per visitor IP (`cf-connecting-ip`), else `429`. Production and the dev link use separate namespaces (`1001`, `1002`). The limit is approximate and per Cloudflare location, which is enough for a contact form.
  3. Size: a body over 64 KB is refused with `413` before parsing.
  4. Honeypot: a hidden text field named `website` that people never see or reach by keyboard. A request with it filled is answered `200 { ok: true }` and sent nowhere, so a bot learns nothing.
  5. Minimum fill time: the form reports `elapsedMs`, the time from the form becoming usable to Submit. Under 3 seconds is treated like the honeypot (answered `200`, sent nowhere).
  6. Validation: the same `contactRequestSchema` the form uses, with the allowed dropdown keys read from content at runtime (the services' slugs, `contact.form.projectTypes`, `contact.form.lodOptions`), else `400 { ok: false, errors }` with codes.
- **The email**: to `CONTACT_TO_EMAIL` (default `info@bimdelivery.vn`), from `CONTACT_FROM_EMAIL` (default `BIM Delivery website <website@bimdelivery.vn>`), `reply_to` the visitor's address so Reply answers them. Plain text only (nothing typed is ever read as HTML). Field names and dropdown choices are printed with their labels from the `contact` content entry. The subject is `New enquiry from <name>`, plus the company when given; it is an internal notification for the team, not visitor copy, so its few fixed words live in `src/lib/contact-email.ts`.
- **Idempotency**: the Resend `Idempotency-Key` is `contact-enquiry/<SHA-256 of the checked request>`, so a double submit or a retry of the identical enquiry within 24 hours sends one email, while an edited enquiry gets a new key.
- **Responses** the form maps: `200 { ok: true }` → success; `400 { ok: false, errors }` → `invalid`; anything else (`403`, `413`, `429`, `502`, a network failure) → `failed`, which shows `contact.errors.deliveryFailed` followed by the email address as a `mailto:` link.
- **Failure is loud and private**: a missing `RESEND_API_KEY`, a Resend error, or a timeout (10 seconds) logs one line naming the cause and the Resend status, never the enquiry, and answers `502`. Nothing typed is put in a URL, storage, a cookie, or a log.
- **Config**: `RESEND_API_KEY` is a Cloudflare secret on the production Worker (`wrangler secret put RESEND_API_KEY`), read through `astro:env/server` (optional at build, so builds never need it). `CONTACT_TO_EMAIL` and `CONTACT_FROM_EMAIL` are public server env fields with the defaults above. The dev link Worker has no key, so its form reports a delivery failure and never sends a real enquiry.

## Requirements

Seeds from the scope's "the message actually reaches an inbox, with spam protection":

- **AC-1**: `/contact-us` shows no captcha widget and makes no request to `challenges.cloudflare.com`.
- **AC-2**: A valid enquiry submitted on `bimdelivery.vn` arrives at `info@bimdelivery.vn` as one plain text email with every filled field (dropdowns as their labels), and Reply addresses the visitor.
- **AC-3**: The form shows the thank you panel only after the endpoint answers `200`. A `400` shows the field errors; any other failure shows the delivery message with the email link, and every typed value stays.
- **AC-4**: A request with the honeypot filled, or sent under 3 seconds, gets `200` and sends nothing. A request from another origin gets `403`. The sixth request in a minute from one IP gets `429`. A body over 64 KB gets `413`. An invalid body gets `400` with codes, checked by the same schema as the form.
- **AC-5**: Every page is still prerendered: `dist/client/` has one HTML file per route, and `/api/contact` is the only on demand route.
- **AC-6**: No enquiry content appears in any log line. Without `RESEND_API_KEY` the endpoint answers `502` and logs that the key is missing.
- **AC-7**: `pnpm check`, `pnpm lint`, and `pnpm build` pass, and `pnpm exec wrangler deploy --dry-run` accepts the config.
